# Repo Notes

Maintenance gotchas for agents working on **this** repo. Personal coding rules live in the global `engineering-rules` skill, not here. Human-facing docs start at [README.md](README.md); linking details are in [docs/linking.md](docs/linking.md).

- Write maintained skill and rule instructions in English. The language of these source documents is separate from the language used to reply to the user.
- `skills/` contains hand-written repo-owned skill packages. Edit `skills/<name>/SKILL.md` for real local skills; these files may use `{{REPO_ROOT}}`.
- `agents/` contains hand-written role sources. Edit each role's `AGENT.md` and `agent.json`; `pnpm skills link` renders native definitions for Claude Code, Kimi Code, OpenCode, Pi, and Antigravity, plus `generated/agents/INDEX.md` for automatic role routing. Keep role selection criteria in the manifest's `description`.
- `teams/` may contain reusable task graphs (currently none). Each `teams/<name>/team.json` assigns tasks to agents and declares prerequisite task IDs in `dependsOn`; `TEAM.md` explains when and how to use the template. Independent ready tasks may run in parallel, while dependencies impose order. Save a template only when the user asks.
- Role-only local skills live under `skills/`; vendored role-only skills come from `vendor/`. Declare both in `agentOnlySkills` in `meta.ts` and the owning role's `agentOnlySkills` manifest field so they are rendered or synced but not installed globally.
- `rules/` and `knowledge/` contain document sources. Document-backed skills such as rule or knowledge wrappers are declared in `meta.ts`, not hand-written under `skills/`. Skills in `alwaysOnInstructionSkills` must be document-backed.
- `generated/` contains rendered agent definitions and rendered or vendored installable skill bundles. `pnpm skills link` renders local sources into it; `pnpm skills sync` copies vendored skills into it. Don't hand-edit generated files.
- `local/` is Git-ignored private state: `project-workspaces/` (project association YAML), `apifox/` (credentials), `server-ops/` (server inventory), and `skill-feedback/` (opt-in marker and reports). `project-init` writes maps explicitly; ordinary discovery only reads them. Keep live agent/MCP configuration in the member repositories. Never copy `local/` content into generated bundles or commits.
- Workspace integration resources retain the ZenTao/PG/Apifox binding schemas; member `bindings` select them explicitly. Use `projectBindings.ts` for source resolution and `integrationContracts.ts` for validation. A workspace reference is authoritative; legacy files remain the fallback only for unmigrated members. Ordinary queries never migrate or delete configuration.
- `meta.template.ts` holds committed shared defaults; `meta.ts` is the Git-ignored local copy that scripts prefer through `scripts/lib/config.ts` (falling back to the template without writing files). Change shared defaults in the template and machine-specific choices in `meta.ts`; never overwrite an existing `meta.ts`. Skill names come from the `Skill` const object, not a TS `enum`: Node runs these `.ts` files in type-stripping mode, which forbids non-erasable syntax. Types live in `scripts/lib/metaTypes.ts`.
- Scripts: `scripts/skills.ts` is the CLI command registry, each command is a file under `scripts/commands/`, and shared code lives in `scripts/lib/`. `commands/link.ts` is a thin orchestrator over `linkTargets`. Tests live under `scripts/tests/`; run `pnpm test`, `pnpm lint`, and `pnpm typecheck`.
- `pnpm skills <command>` is the single entry point: `status`, `link`, `unlink`, `sync`, `init`, `check`, `cleanup`, `validate`, `note`, `feedback`, `project`.
- Linking gotchas (see [docs/linking.md](docs/linking.md) for the target table): Codex, Pi, Antigravity, and `~/.agents/skills` omit the four rules delivered through managed global sections (`communication-rules`, `agent-routing`, `project-workspaces`, `skill-feedback`); Claude Code and OpenCode get `alwaysOnInstructionSkills` as rule files instead of skills. Only skill targets with `createIfParentExists` may create a missing directory under an existing host parent. Gemini CLI-specific targets and role generation are not configured; see [docs/antigravity.md](docs/antigravity.md), and don't symlink plain rule wrappers into Antigravity's trigger-based rule directory. Preserve user content: unlink removes only repo-owned links and managed sections, and leaves json-array/json-object entries (including OpenCode's `permission.external_directory`) in place.
